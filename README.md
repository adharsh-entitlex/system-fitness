# THE SYSTEM — Personal Fitness Interface

A Solo Leveling–inspired personal fitness, hydration and nutrition tracker built for **Adharsh M**.

Plain HTML, CSS and JavaScript (installable PWA) with two interchangeable backends: a
zero-dependency Node server for local use and a Cloudflare Worker + D1 deployment for the
hosted version. No build step and no framework.

- **Hosted:** <https://the-system-fitness-ehtabh.freebuff.site>
- **Preview:** <https://the-system-fitness-ehtabh-preview.freebuff.site>

Open the hosted link on any phone or laptop, sign nothing, and every device shares the same
record. Install it from Chrome's menu to run it as a standalone app.

## Run it locally

```bash
npm start            # node server/server.mjs — serves public/ and the JSON API
```

Then visit <http://localhost:3000>. Use `PORT=8080 npm start` to change the port. The record
is written to `data/state.json` (gitignored).

You can also serve `public/` with any static host (`python3 -m http.server 3000 -d public`).
The app then runs **local only** on `localStorage` and the footer says so.

## Screens

- **Today** — daily workout quest with checkable exercises, skip/undo, hydration ring with reminders, streak and weekly progress.
- **Workouts** — editable workout library (name, exercises, sets, reps, weight) plus a weekly schedule.
- **Nutrition** — calorie and protein goals, meal log, an editable pantry (built-in ingredient groups plus your own additions, renameable and removable), and Kerala dish suggestions that only use the ingredients you have.
- **History** — every logged session with the exercises and weights you actually used, filterable by cleared, skipped or last 7 days.
- **Progress** — 12-week quest map, streaks and a hydration chart.
- **Trainer** — notes generated from your own data: what to train next, protein and water gaps, progressive overload suggestions.

## API

Both backends expose the same three routes, so the frontend does not care which one it talks to.

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `/api/health` | GET | Liveness probe, used by the app to detect the backend |
| `/api/state` | GET | The saved record: `{ revision, updatedAt, savedAt, state }`, or 404 when empty |
| `/api/state` | PUT | Save `{ state, updatedAt }`; **409** plus the stored record when the incoming copy is older |

The Node server writes `data/state.json` atomically (tmp + rename, serialised writes) and caps
request bodies at 4 MB. The Worker keeps one row in D1 and uses a conditional upsert as its
conflict guard.

## Sync behaviour

- The server is canonical; `localStorage` is the offline cache.
- Every change is pushed after ~1 second. While the server is unreachable the app keeps working
  and retries on the `online` event, on tab focus, and on the next change.
- Last write wins on `meta.updatedAt`. A tab that receives a newer copy — from another tab via
  the `storage` event, or from the server after a 409 — adopts it instead of overwriting it.
- Nothing is merged field by field, so two devices editing at the same moment keep the newer
  whole record. For one person switching devices this is effectively always the right answer.

## Data — where your history lives

1. **Server** — `data/state.json` locally, or the `record` table in D1 when hosted.
2. **`localStorage['system-fitness-v1']`** — the offline cache in each browser.

The object holds workout logs (`logs`, keyed `YYYY-MM-DD`), water (`water`, `waterBonus`),
meals (`meals`), templates, weekly schedule, pantry, goals, nutrition targets, XP and
`meta.updatedAt`.

The gear icon holds **EXPORT BACKUP** and **IMPORT BACKUP** (`system-fitness-backup-YYYY-MM-DD.json`)
as a third copy. Export one occasionally; the database is the thing a cleared browser cannot take
away from you.

## Hosting

The hosted build is a Worker (`worker/index.js`) serving `public/` and a D1 database named `DB`.
Deploys are done from the Freebuff Sites panel; `sites.json` is the manifest it uses.

```bash
npm run worker       # local Worker on http://localhost:8787 with local D1
```

**There is no authentication.** The URL is unlisted, not private: anyone who has it can read and
write the record. Keep the link to yourself, or put Sign in with Freebuff / Cloudflare Access in
front of it before sharing. The local Node server has the same property — keep it on localhost or
a private network.

## Android

### Install without an APK (works today)

Open the hosted URL in Chrome on Android and choose **Install app** (or ⋮ → *Add to Home screen*).
Chrome installs the PWA as a standalone app with its own icon, no address bar, offline shell and
`targetSdk` behaviour of the current browser. The manifest sets `display: standalone`,
`orientation: any`, full-bleed theming and maskable icons; the layout respects
`env(safe-area-inset-*)` and `interactive-widget=resizes-content` so the keyboard resizes the
viewport instead of covering inputs, and it stays resizable on large screens the way Android 17
(API 37) requires.

### Build an APK (Trusted Web Activity)

`android/twa-manifest.json` is ready for [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap)
with `minSdkVersion 24` and `targetSdkVersion 37` (Android 17). Building needs a JDK 17 and the
Android SDK on your machine — they are not part of this repo:

```bash
npm i -g @bubblewrap/cli
bubblewrap init --manifest https://the-system-fitness-ehtabh.freebuff.site/manifest.webmanifest
bubblewrap build          # → app-release-signed.apk
```

For the APK to run without a browser address bar, the site must trust the signing key: copy the
SHA-256 from `bubblewrap fingerprint` into `public/.well-known/assetlinks.json` and redeploy.
Google Play additionally requires `targetSdk` 36+ today and 37 from August 2027.
